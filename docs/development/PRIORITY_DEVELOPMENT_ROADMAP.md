# GraphQL API 우선순위 개발 로드맵

> **역사적 참고 자료**: 이 문서는 초기 GraphQL 기능 개발의 기록이다. 현재 외부 MCP·GraphQL 운영 경계, 도구 계약, 전문 검색, 표 동기화의 우선순위와 완료 조건은 단일 기준 문서인 [운영 준비도 명세](../../specs/008-production-readiness/spec.md)를 따른다. 새 작업 계획이나 완료 판정에는 이 문서의 Phase·일정 정보를 사용하지 않는다.

bun-graph-db의 핵심 기능부터 순차적으로 개발하기 위한 Phase 기반 우선순위 로드맵입니다.

## 📊 현재 구현 상태

### ✅ Phase 1: 핵심 기능 (완료)
**전체 진행률**: 19/19 (100%)

- **Phase 1A**: 노드 관리 (6/6) - 기본 CRUD 완료
- **Phase 1B**: 테이블 관리 (6/6) - 안전장치 구현 완료  
- **Phase 1C**: 템플릿 시스템 (7/7) - AI 친화적 기능 완료

**주요 성과**:
- deleteTable 안전장치: 의존성 검사 및 연쇄 삭제 옵션
- executeTemplate JSON Schema 검증: 타입 검사 및 필수 필드 검증
- 포괄적인 단위 테스트 스위트: 33개 테스트, 73개 검증 케이스

## 🎯 Phase 2: 관계 및 속성 시스템 (다음 목표)

### Phase 2A: 관계 관리 (그래프 DB 핵심)
**목표**: 진정한 그래프 데이터베이스 기능 구현
**API 개수**: 8개

**핵심 기능**:
- 노드 간 관계 생성 및 관리
- 그래프 탐색 및 검색 기능
- 의존성 체인 분석
- 관계 타입 관리

**중요도 분석**:
- **High**: nodeRelations, searchRelatedNodes, createRelation, deleteRelation
- **Medium**: getDependencyChain, createRelationType  
- **Low**: relationType, relationTypes (메타데이터 조회)

### Phase 2B: 속성 스키마 관리 (동적 스키마)
**목표**: 테이블별 동적 속성 정의 시스템
**API 개수**: 6개

**핵심 기능**:
- 동적 폼 생성을 위한 메타데이터 제공
- 속성 타입 정의 및 관리
- 노드별 속성 값 설정 및 검증

**주요 이점**:
- JSON Schema 기반 속성 검증
- 동적 UI 생성 지원
- 타입 안전성 보장

## 🔍 Phase 3: 고급 검색 및 분석 (3-4주차)

### Phase 3A: 검색 시스템
**목표**: 사용자 경험 핵심 검색 기능
**현재 상태**: 1/2 구현 완료

**주요 이슈**:
- advancedSearch: 보안 검토 필요 (SQL Injection 방지)
- 성능 최적화: 인덱스 활용 및 쿼리 캐싱

### Phase 3B: 분석 및 집계  
**목표**: AI가 활용할 그래프 분석 기능
**현재 상태**: Mock 구현 → 실제 구현 전환 필요

**구현 필요사항**:
- 실제 그래프 알고리즘 구현
- SQL 집계 로직 전환
- 성능 최적화

## 📈 개발 전략

### Phase 2 개발 접근법
1. **관계 시스템 우선**: Phase 2A 완전 구현 후 2B 진행
2. **성능 중심**: 그래프 탐색 알고리즘 최적화에 집중
3. **데이터 정합성**: 순환 참조 방지 및 관계 무결성 보장
4. **테스트 주도**: 복합 관계 시나리오 E2E 테스트 작성

### 품질 게이트
- **기능 완성도**: Phase별 100% API 구현
- **성능 기준**: 관계 탐색 < 500ms (복잡도에 따라 조정)
- **데이터 무결성**: 관계 생성/삭제 시 일관성 보장
- **테스트 커버리지**: 80% 이상 유지

## 🚨 위험 요소 및 대응

### 높은 우선순위 위험
1. **관계 탐색 성능**: 대용량 그래프에서의 성능 저하
   - 대응: 깊이 제한, 인덱스 최적화, 캐싱 전략
2. **순환 참조**: 무한 루프 가능성
   - 대응: 탐색 깊이 제한, 방문 노드 추적
3. **데이터 일관성**: 관계 삭제 시 고아 데이터 발생
   - 대응: 트랜잭션 기반 연쇄 업데이트

### 중간 우선순위 위험
1. **동적 스키마 복잡성**: 속성 검증 로직 복잡도 증가
2. **메모리 사용량**: 대규모 관계 그래프 메모리 점유

## 🛠 도구 및 자동화 계획

### Phase 2 전용 도구
- **관계 무결성 검증**: 자동화된 일관성 체크
- **그래프 시각화**: 개발 단계에서 관계 구조 확인
- **성능 모니터링**: 쿼리 실행 시간 및 리소스 사용량 추적

### 확장된 테스트 전략
- **관계 시나리오 테스트**: 복합 관계 생성/삭제 시나리오
- **성능 벤치마크**: 다양한 그래프 크기에서의 성능 측정
- **부하 테스트**: 동시 관계 조작 시의 안정성 검증
