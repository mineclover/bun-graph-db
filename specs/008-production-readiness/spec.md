# 기능 명세: 운영 가능한 AI 그래프 플랫폼

**Feature Branch**: `008-production-readiness`  
**작성일**: 2026-08-10  
**마지막 검증일**: 2026-08-11  
**상태**: Active  
**기준 언어**: 한국어  
**범위**: MCP, GraphQL, 검색, 표 형식 동기화의 운영 준비도

## 목적

Bun Graph Database를 외부 AI 클라이언트와 운영자가 안전하게 사용할 수 있는 그래프 플랫폼으로 발전시킨다. 이 명세는 이미 제공되는 테이블·노드·관계·템플릿 기능을 대체하지 않는다. 대신 접근 제어, 계약 일관성, 검색 품질, 동기화 신뢰성을 추가한다.

## 사용자 시나리오와 검증

### 접근이 통제된 AI 작업

권한을 가진 AI 클라이언트는 루트 또는 테이블 MCP 엔드포인트에서 자신에게 허용된 도구만 발견하고 실행한다. 권한이 없거나 범위를 벗어난 요청은 데이터나 도구 정보를 노출하지 않고 거부된다.

### 계약과 구현이 함께 변경되는 도구

운영자는 GraphQL 기능을 MCP 도구로 제공할 때 하나의 계약을 수정한다. 배포 전 검증은 계약, 도구 목록, 입력 스키마 사이의 차이를 실패로 처리한다.

### 정확한 텍스트 탐색

사용자는 테이블 범위와 필터를 유지한 채 노드 내용을 검색하고, 관련도 순서와 페이지 경계를 재현 가능한 결과로 받는다.

### 복구 가능한 표 동기화

운영자는 승인된 대상에 데이터를 동기화하고, 실패·재시도·결과를 확인한다. 파일 대상은 부분 쓰기로 기존 파일을 손상시키지 않으며, 미지원 대상은 활성화할 수 없다.

## 기능 요구사항

### M1. 접근 제어와 운영 제한

- **FR-001**: MCP, GraphQL, REST의 외부 쓰기 작업은 인증된 주체와 연결되어야 한다.
- **FR-002**: 주체별 권한은 전역 작업과 테이블 범위 작업을 구분해야 한다.
- **FR-003**: 도구 목록, 도구 호출, GraphQL·REST·스키마 요청은 허용된 작업만 반환하거나 실행해야 한다.
- **FR-004**: 거부된 요청은 대상 테이블의 존재 여부, 도구 정의, 데이터 내용을 노출해서는 안 된다.
- **FR-005**: 운영자는 요청 주체, 대상, 작업 종류, 결과를 추적할 수 있어야 하며 비밀 값과 원문 인수는 기록하지 않아야 한다.
- **FR-006**: MCP·GraphQL·REST·스키마 외부 요청은 배포 정책에 따른 origin, 요청 크기, 빈도, GraphQL 복잡도 제한을 통과해야 한다. 내부 MCP REST 브리지는 별도의 고엔트로피 Bearer 자격 증명을 전달해야 한다.

### M2. 단일 계약 기반 MCP 도구

- **FR-007**: 공개 MCP 도구는 하나의 버전 관리 계약에서 이름, 설명, 입력 스키마, 읽기·쓰기 성격, 범위를 얻어야 한다.
- **FR-008**: 계약에 없는 공개 도구와 구현되지 않은 계약 도구는 배포 검증에서 실패해야 한다.
- **FR-009**: 클라이언트가 받는 `tools/list` 결과는 계약 버전과 일치하고 결정적으로 정렬되어야 한다.
- **FR-010**: 테이블별 도구는 공통 계약을 유지하면서 해당 테이블에 허용된 템플릿과 작업만 노출해야 한다.

### M3. 전문 검색

- **FR-011**: 사용자는 테이블 범위, 속성 필터, 페이지 옵션을 유지한 텍스트 검색을 수행할 수 있어야 한다.
- **FR-012**: 검색 결과에는 안정적인 관련도 순서와 검색 이유를 확인할 수 있는 최소한의 메타데이터가 포함되어야 한다.
- **FR-013**: 검색 인덱스를 생성·갱신·복구하는 과정은 기존 노드 데이터의 읽기·쓰기를 손상시키지 않아야 한다.

### M4. 표 형식 동기화 신뢰성

- **FR-014**: 활성화 가능한 동기화 대상은 실제 읽기·쓰기 검증을 통과해야 하며, 실패한 활성화는 기존 활성 설정을 바꾸면 안 된다.
- **FR-015**: 파일 기반 내보내기는 원자적으로 완료되거나 기존 파일을 보존해야 한다.
- **FR-016**: 동기화 실패와 재시도 결과는 영속된 이벤트 이력에서 조회할 수 있어야 한다.
- **FR-017**: 운영자는 실패한 동기화를 일시 중지, 재개 또는 수동 재실행할 수 있어야 한다.

## 핵심 엔터티

- **Principal**: 인증된 요청 주체와 역할·테이블 범위를 나타낸다.
- **Permission Grant**: 주체가 전역 또는 특정 테이블에서 수행할 수 있는 읽기·쓰기·관리 작업을 나타낸다.
- **MCP Tool Contract**: 공개 도구의 안정적 이름, 입력, 권한, 범위, 계약 버전을 나타낸다.
- **Search Index**: 노드 텍스트와 검색 메타데이터의 최신 상태를 표현한다.
- **Sync Delivery**: 대상, 시도 횟수, 결과, 복구 가능한 실패 정보를 나타낸다.

## 작업 순서와 완료 조건

1. **M1**을 먼저 완료한다. 인증·권한·제한·감사 검증 없이 외부 노출 범위를 넓히지 않는다.
2. **M2**에서 MCP 도구 계약을 단일화한다. 이후 새 기능은 계약과 검증을 함께 추가한다.
3. **M3**에서 전문 검색을 제공한다. 벡터 또는 임베딩 검색은 이 단계의 필터·권한·평가 기준 위에서만 추가한다.
4. **M4**에서 파일 동기화와 복구 동작을 완료한다. 양방향 동기화와 파일을 원본으로 하는 읽기는 이 범위에 포함하지 않는다.

각 단계는 해당 기능 요구사항의 계약·통합·회귀 테스트가 통과할 때만 완료된다. M1과 M2가 완료되기 전에는 새 외부 MCP 쓰기 기능을 추가하지 않는다.

## 운영 설정 기준

- production에서는 `BUN_GRAPH_DB_AUTH_REQUIRED`가 기본적으로 `true`다. 명시적으로 `false`로 설정한 개발 환경만 익명 접근을 허용한다.
- `BUN_GRAPH_DB_ACCESS_TOKENS`는 자격 증명 문자열을 키로 하고 `{ "id", "role", "tableIds" }`를 값으로 하는 JSON 객체다. 역할은 `reader`, `writer`, `admin`이며 `tableIds`의 `"*"`는 모든 테이블을 뜻한다.
- `BUN_GRAPH_DB_API_TOKEN`은 기존 배포를 위한 전역 `admin` 호환 토큰이다. 새 배포는 복수 토큰 설정을 사용한다.
- `BUN_GRAPH_DB_ALLOWED_ORIGINS`, `BUN_GRAPH_DB_RATE_LIMIT_ENABLED`, `BUN_GRAPH_DB_RATE_LIMIT_MAX`, `BUN_GRAPH_DB_RATE_LIMIT_WINDOW_MS`, `BUN_GRAPH_DB_MAX_REQUEST_BYTES`, `BUN_GRAPH_DB_GRAPHQL_MAX_COMPLEXITY`로 브라우저 origin·요청률·본문 크기·GraphQL 필드 복잡도를 설정한다. 기본 본문 한도는 1 MiB, 기본 GraphQL 복잡도 한도는 250 필드다. 모든 접근 판정 로그는 주체·엔드포인트·작업·테이블만 기록하며 토큰과 원문 인수는 기록하지 않는다. 인증이 켜진 배포는 내부 MCP 브리지용 `BUN_GRAPH_DB_INTERNAL_BRIDGE_TOKEN`을 32자 이상으로 설정해야 한다.
- MCP 루트 도구 계약의 현재 버전은 `2026-08-10.1`이다. 각 도구의 `action`(`read` 또는 `write`)과 `scope`는 `tools/list` 메타데이터와 요청 권한 판정의 단일 기준이다. 알 수 없거나 인수가 불완전한 도구 호출은 보수적으로 쓰기 권한을 요구한다.
- 노드 텍스트 검색은 SQLite FTS5 인덱스를 사용하며, 테이블 범위·기존 속성 필터·페이지 경계를 유지한다. 결과의 `relevanceScore`는 FTS 정렬 점수에서 유도하고, 명시적 정렬이 없을 때는 관련도와 노드 ID를 기준으로 재현 가능하게 정렬한다.
- 동기화 전달은 SQLite 작업 원장에 `queued`, `running`, `retry_wait`, `paused`, `succeeded`, `failed` 상태·임대·시도 횟수·다음 시도 시각을 영속한다. 재기동 시 미완료 임대는 복구하고 실패는 최대 다섯 번 지수 백오프로 재시도한다. 운영자는 pause, resume, retry로 실패 작업을 제어할 수 있다.
- Excel 파일 대상은 SheetJS CE `0.20.3`으로 `.xlsx` 파일을 작성한다. 활성화 전 대상 읽기와 쓰기 가능성을 검사하고, 쓰기 결과는 같은 디렉터리의 임시 파일을 다시 열어 검증한 뒤 원자적으로 교체한다. 실패하면 기존 대상 파일과 활성 설정을 보존한다.

## 범위 제외

- 특정 ID 공급자, SSO 제공자, 사용자 인터페이스의 선택
- 벡터 데이터베이스와 임베딩 모델의 선택
- Excel 또는 Sheets를 원본 데이터베이스로 사용하는 양방향 동기화
- 현재 데이터 모델을 멀티테넌트 저장소로 이전하는 작업
